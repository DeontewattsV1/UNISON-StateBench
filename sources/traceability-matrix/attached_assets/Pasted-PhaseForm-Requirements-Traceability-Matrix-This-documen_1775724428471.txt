PhaseForm Requirements & Traceability Matrix

This document captures the formal requirements for the PhaseForm adaptive, self-healing conductor and traces each requirement to corresponding verification activities and acceptance thresholds. It is aligned with the four-layer architecture (L1-L4) and safety invariants defined in the PhaseForm blueprint and design document.

Traceability Matrix
Requirement ID

Experiment / Test Case

Acceptance Threshold

R-01

Induce mechanical strain (cut, tear) on the substrate. Measure conductivity recovery and self-healing time using strain and continuity sensors.

Conductivity recovers autonomously within 2 minutes for minor damage and within 12 minutes for major cracks without manual intervention.

R-02

Attempt to force the conductor into states outside the prevalidated set by randomizing actuation commands.

System rejects invalid states; only transitions to the defined 8–16 allowed states are possible; no undefined state occurs.

R-03

Execute repeated reconfiguration cycles and measure insertion loss at 2.4 GHz using a network analyzer before and after each cycle.

Insertion loss remains below 0.5 dB across cycles; no progressive degradation beyond the specified RF loss envelope.

R-04

Create controlled damage scenarios (oxidation, small cut, foreign object) and verify that resistance, strain and temperature sensors detect and classify damage.

Damage detection and classification occur within 100 ms with at least 90 % true positive accuracy and less than 5 % false positives.

R-05

Send unsigned, tampered or invalid OTA update packets to the controller and monitor state changes.

Device rejects all unsigned or invalid payloads; zero unauthorized state transitions occur under any tested attack scenario.

R-06

Interrupt an OTA update mid-transfer (simulate power failure); then resume power and complete the update.

Device rolls back to the last stable state immediately and successfully applies the update upon resumption without data corruption.

R-07

Inspect the memory and logging of L1-L3 layers after profile updates and conduct user data audits.

Personal data remains exclusively within the secure element and cloud; no user-specific data persists in the material or local control layers.

R-08

Collect distinct usage telemetry from two separate users and run behavioral inference to generate personalized state deltas.

Device applies different valid states for distinct users and produces consistent states for repeated sessions with the same user in over 95 % of trials.

R-09

Inflict irrecoverable damage (e.g., large tear destroying microchannel geometry) and observe device behavior.

Device enters a passive-safe mode, ceases reconfiguration attempts, and maintains safe operation without emitting heat or current beyond safe limits.

R-10

Perform multiple cycles of cutting the conductor and applying RF heating or electrowetting to heal and reconfigure.

Conduction is restored after each cycle; no overheating beyond safe thermal limit (e.g., 65 °C); at least 20 consecutive repairs occur without significant performance decline.
